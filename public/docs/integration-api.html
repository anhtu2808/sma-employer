Integration API Documentation

Integrate SmartRecruit with third-party systems to parse resumes, score candidates against a job description, and retrieve asynchronous results through polling or webhooks.

PARSING MATCHING PARSING_AND_MATCHING

Authentication

Every request must include the X-API-Key header.

Request Format

Create jobs with multipart/form-data and up to 10 resume PDFs per request.

Result Delivery

Use webhooks for notifications, then call /results to fetch the final payload.

Important: This page focuses on API integration only. SmartRecruit provisions apiKey, webhookSecret, and feature scope separately.

01

Quick Start

1. Receive your API key

Confirm whether your key is scoped for PARSING, MATCHING, or PARSING_AND_MATCHING.

2. Create a job

Upload 1 to 10 resume PDFs through multipart/form-data. Matching also requires jdText or jdFile.

3. Store the identifiers

The initial response confirms job creation. Persist both jobId and externalRequestId.

4. Fetch the final result

Track status by polling or webhook. When the job finishes, call GET /jobs/{id}/results.

02

Authentication & Scope

All integration endpoints require the API key in the request header:

X-API-Key: <your-api-key>
ScopeAllowed EndpointsNotes
PARSINGPOST /parsing-jobsResume parsing only.
MATCHINGPOST /matching-jobsThe final payload contains only matchingResult.
PARSING_AND_MATCHINGAll integration endpointsReturns both parsing and matching output.

Job ownership rule: only the API key that created a job can retrieve its status and results.

03

Endpoint Overview

Use CaseEndpointWhen to Use It
Resume parsingPOST /parsing-jobsExtract structured data from resumes.
JD matchingPOST /matching-jobsScore candidates against a job description.
Parsing + matchingPOST /parsing-matching-jobsReturn both parsingResult and matchingResult.
Progress checkGET /jobs/{id}Get job-level and item-level status only.
Final resultGET /jobs/{id}/resultsRetrieve the detailed parsing and matching payload.

File rules

Resume files must be PDF. If you send a JD file, jdFile must also be a PDF.

Batch size

Each request accepts at least 1 and at most 10 resume files.

Time format

All timestamps use ISO-8601 formatting.

Create Jobs

A. Parsing Job

FieldRequiredTypeDescription
cvFilesYesfile[]List of resume PDF files.
webhookUrlNostringPer-request webhook override.
externalRequestIdNostringYour own business identifier for this submission.
 
curl --location 'https://your-domain.com/v1/integration/parsing-jobs' \
  --header 'X-API-Key: sma_xxx' \
  --form 'externalRequestId=REQ-20260406-001' \
  --form 'cvFiles=@"/path/to/cv-1.pdf"' \
  --form 'cvFiles=@"/path/to/cv-2.pdf"'

B. Matching Job

FieldRequiredTypeDescription
cvFilesYesfile[]List of resume PDF files.
jdTextConditionallystringJob description as plain text.
jdFileConditionallyfileJob description as a PDF file.
webhookUrlNostringPer-request webhook callback URL.
externalRequestIdNostringYour own business identifier for this submission.
  • You must send at least one of jdText or jdFile.
  • If both are provided, the system prioritizes jdText.
  • With MATCHING scope, parsingResult is always null.
curl --location 'https://your-domain.com/v1/integration/matching-jobs' \
  --header 'X-API-Key: sma_xxx' \
  --form 'externalRequestId=REQ-20260406-002' \
  --form 'jdText=Senior Java Developer with Spring Boot, PostgreSQL, REST API and Docker.' \
  --form 'cvFiles=@"/path/to/cv-1.pdf"'

C. Parsing and Matching Job

The form fields match the matching job, but the final payload includes both parsingResult and matchingResult.

curl --location 'https://your-domain.com/v1/integration/parsing-matching-jobs' \
  --header 'X-API-Key: sma_xxx' \
  --form 'externalRequestId=REQ-20260406-004' \
  --form 'jdFile=@"/path/to/jd.pdf"' \
  --form 'cvFiles=@"/path/to/cv-1.pdf"' \
  --form 'cvFiles=@"/path/to/cv-2.pdf"'

05

Polling & Results

  1. Create the job and store both jobId and externalRequestId.
  2. Poll GET /v1/integration/jobs/{id} to track progress.
  3. When the job reaches COMPLETED, PARTIAL, or FAILED, call GET /v1/integration/jobs/{id}/results.
  4. Inspect each item to determine which resumes succeeded or failed.
  • GET /jobs/{id}: returns job and item status only, without the detailed parsing or matching payload.
  • GET /jobs/{id}/results: returns the full response including parsingResult and matchingResult when available.
GET /v1/integration/jobs/{id}
GET /v1/integration/jobs/{id}/results

06

Webhook Callback

  • A webhook is sent whenever an individual item changes status.
  • A webhook is also sent whenever the overall job status changes.
  • If the request does not provide webhookUrl, the system uses the API key's defaultWebhookUrl.
  • If the request provides webhookUrl, it is only accepted when allowWebhookOverride = true.
Content-Type: application/json
X-SmartRecruit-Event: integration.job.updated | integration.job.item.updated
X-SmartRecruit-Timestamp: <epoch-seconds>
X-SmartRecruit-Signature: sha256=<hex>

Verify Signature

Webhook requests are signed with the API key's webhookSecret, not the apiKey. Build the signed string using this format:

<timestamp>.<raw-json-body>
signedPayload = timestamp + "." + rawBody
expected = "sha256=" + HMAC_SHA256_HEX(webhookSecret, signedPayload)
compare(expected, X-SmartRecruit-Signature)
07

Statuses

Job Status

PENDING The job has been created but processing has not started yet.
PROCESSING The system is actively processing one or more items.
PARTIAL Some items succeeded while others failed, or the job finished with mixed outcomes.
COMPLETED Every item finished successfully.
FAILED Every item failed.

Item Status

PENDING The item has been created but has not started processing.
PARSING The resume is currently being parsed.
MATCHING The resume is currently being evaluated against the job description.
COMPLETED The item finished successfully.
FAILED The item failed.

09

Integration Checklist

Before go-live

  • You have received both apiKey and webhookSecret.
  • You know the feature scope of the key and the correct base URL for each environment.
  • Your client supports multipart/form-data uploads.
  • All resume files are valid PDF documents.
  • You are ready to supply jdText or jdFile for matching flows.

Best practices

  • Send externalRequestId so you can map SmartRecruit jobs back to your own system.
  • Handle idempotency on the client side to avoid duplicate submissions.
  • Use webhooks for notifications and /results for final data retrieval.
  • Always persist jobId and keep polling as a fallback path.
  • Verify the webhook signature before processing any business logic.
