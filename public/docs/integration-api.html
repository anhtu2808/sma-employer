Integration API Documentation

Hướng dẫn tích hợp Smart Recruit cho bên thứ ba để parse CV, chấm điểm theo JD và lấy kết quả bất đồng bộ bằng polling hoặc webhook.

PARSINGMATCHINGPARSING_AND_MATCHING

Authentication

Mọi request dùng header X-API-Key.

Request Format

Tạo job bằng multipart/form-data, tối đa 10 CV PDF.

Result Delivery

Nhận tín hiệu qua webhook hoặc polling rồi gọi /results.

Lưu ý: Trang này chỉ tập trung vào hướng dẫn tích hợp API. Việc cấp apiKey, webhookSecret và scope được Smart Recruit xử lý riêng.

01

Quick Start

1. Nhận API key

Xác nhận scope là PARSING, MATCHING hoặc PARSING_AND_MATCHING.

2. Tạo job

Upload 1 đến 10 CV PDF bằng multipart/form-data. Matching cần thêm jdText hoặc jdFile.

3. Lưu jobId

Response đầu tiên chỉ là thông tin khởi tạo. Hãy lưu jobId và externalRequestId.

4. Lấy kết quả

Theo dõi trạng thái qua polling hoặc webhook. Khi job kết thúc, gọi GET /jobs/{id}/results.

02

Authentication & Scope

Tất cả endpoint integration dùng API key trong header:

X-API-Key: <your-api-key>
ScopeAllowed EndpointsGhi chú
PARSINGPOST /parsing-jobsChỉ parse CV.
MATCHINGPOST /matching-jobsKết quả cuối chỉ có matchingResult.
PARSING_AND_MATCHINGToàn bộ endpoint integrationTrả đầy đủ cả parse và matching.

Quy tắc truy cập job: chỉ API key đã tạo job mới được phép đọc trạng thái và kết quả của job đó.

File rules

CV bắt buộc là PDF. Nếu gửi JD bằng file thì jdFile cũng phải là PDF.

Batch size

Một request chứa tối thiểu 1 CV và tối đa 10 CV.

Time format

Các mốc thời gian dùng ISO-8601.

Create Jobs

A. Parsing Job

FieldBắt buộcKiểuMô tả

  --header 'X-API-Key: sma_xxx' \
  --form 'externalRequestId=REQ-20260406-001' \
  --form 'cvFiles=@"/path/to/cv-1.pdf"' \
  --form 'cvFiles=@"/path/to/cv-2.pdf"'

B. Matching Job

FieldBắt buộcKiểuMô tả
cvFilesCófile[]Danh sách CV PDF.
jdTextCó điều kiệnstringNội dung JD dạng text.
jdFileCó điều kiệnfileJD PDF.
webhookUrlKhôngstringWebhook callback riêng.
externalRequestIdKhôngstringID nghiệp vụ phía đối tác.
  • Phải có ít nhất một trong hai trường jdText hoặc jdFile.
  • Nếu truyền cả hai, hệ thống ưu tiên jdText.
  • Với MATCHING, parsingResult sẽ là null.
curl --location 'https://your-domain.com/v1/integration/matching-jobs' \
  --header 'X-API-Key: sma_xxx' \
  --form 'externalRequestId=REQ-20260406-002' \
  --form 'jdText=Senior Java Developer with Spring Boot, PostgreSQL, REST API and Docker.' \
  --form 'cvFiles=@"/path/to/cv-1.pdf"'

C. Parsing And Matching Job

Form fields giống matching job, nhưng payload kết quả sẽ trả đầy đủ cả parsingResult và matchingResult.

curl --location 'https://your-domain.com/v1/integration/parsing-matching-jobs' \
  --header 'X-API-Key: sma_xxx' \
  --form 'externalRequestId=REQ-20260406-004' \
  --form 'jdFile=@"/path/to/jd.pdf"' \
  --form 'cvFiles=@"/path/to/cv-1.pdf"' \
  --form 'cvFiles=@"/path/to/cv-2.pdf"'

05

Polling & Results

  1. Gọi API tạo job và lưu jobId, externalRequestId.
  2. Polling GET /v1/integration/jobs/{id} để kiểm tra tiến độ.
  3. Khi job ở trạng thái COMPLETED, PARTIAL hoặc FAILED, gọi GET /v1/integration/jobs/{id}/results.
  4. Đọc kết quả ở từng item để biết CV nào thành công hoặc lỗi.
  • GET /jobs/{id}: chỉ trả trạng thái job và item, không có payload parse/matching chi tiết.
  • GET /jobs/{id}/results: trả toàn bộ trạng thái cùng parsingResult hoặc matchingResult nếu đã có.
GET /v1/integration/jobs/{id}

Webhook Callback

  • Webhook được gọi khi một item thay đổi trạng thái.
  • Webhook cũng được gọi khi trạng thái tổng của job thay đổi.
  • Nếu request không truyền webhookUrl, hệ thống dùng defaultWebhookUrl của API key.
  • Nếu request truyền webhookUrl, điều này chỉ hợp lệ khi allowWebhookOverride = true.
Content-Type: application/json

Verify Signature

Webhook được ký bằng webhookSecret của API key, không dùng apiKey. Chuỗi cần ký có dạng:

<timestamp>.<raw-json-body>
signedPayload = timestamp + "." + rawBody
expected = "sha256=" + HMAC_SHA256_HEX(webhookSecret, signedPayload)
compare(expected, X-SmartRecruit-Signature)

Statuses

Job Status

PENDING Job đã tạo nhưng chưa bắt đầu xử lý.
PROCESSING Các item đang được xử lý.
PARTIAL Có item thành công hoặc thất bại, hoặc job hoàn tất với cả kết quả lẫn lỗi.
COMPLETED Tất cả item xử lý thành công.
FAILED Tất cả item đều thất bại.

Item Status

PENDING Item đã được tạo nhưng chưa xử lý.
PARSING Đang parse CV.
MATCHING Đang chấm điểm theo JD.
COMPLETED Item xử lý thành công.
FAILED Item xử lý thất bại.

Integration Checklist

Before go-live

  • Đã nhận apiKey và webhookSecret.
  • Đã biết scope của key và base URL theo môi trường.
  • Đã hỗ trợ upload multipart/form-data.
  • Đã gửi CV đúng định dạng PDF.
  • Đã chuẩn bị jdText hoặc jdFile cho luồng matching.

Best practices

  • Nên truyền externalRequestId để map job với hệ thống đối tác.
  • Tự xử lý idempotency ở phía client để tránh submit trùng.
  • Dùng webhook để nhận tín hiệu, dùng /results để lấy dữ liệu cuối.
  • Luôn lưu jobId và giữ polling fallback.
  • Verify chữ ký webhook trước khi xử lý nghiệp vụ.
